# Package Dependency Graph

Инструмент визуализации графа зависимостей пакетов.

## Этап 1. Минимальный прототип с конфигурацией

На первом этапе реализован минимальный прототип CLI-приложения, поддерживающий настройку параметров через командную строку.

### Параметры командной строки

Программа принимает следующие параметры:

- `--package` — имя анализируемого пакета;
- `--repository` — URL-адрес репозитория или путь к файлу тестового репозитория;
- `--test-mode` — режим работы с тестовым репозиторием (`true` или `false`);
- `--version` — версия пакета;
- `--output` — имя генерируемого файла с изображением графа;
- `--filter` — подстрока для фильтрации пакетов.

Все параметры являются обязательными.

### Вывод параметров

При запуске приложения выводятся значения всех заданных параметров в формате «ключ — значение».

### Обработка ошибок

Реализована обработка ошибок при передаче пустых строковых значений и недопустимого значения параметра `--test-mode`.

Отсутствие обязательных параметров обрабатывается средствами `argparse`.

### Запуск

Для запуска приложения из корневой директории проекта необходимо выполнить команду:

```
python3 src/main.py \
    --package serde \
    --repository ./repository.json \
    --test-mode true \
    --version 1.0.0 \
    --output graph.png \
    --filter test
```

Пример содержит демонстрационные значения параметров.

### Пример работы

Пример запуска:

```text
$ python3 src/main.py --package serde --repository ./repository.json --test-mode true --version 1.0.0 --output graph.png --filter test
package: serde
repository: ./repository.json
test_mode: True
version: 1.0.0
output: graph.png
filter: test
```

На первом этапе приложение выводит параметры конфигурации. Получение зависимостей и построение графа будут реализованы на следующих этапах.

### Тестирование

На первом этапе автоматические тесты не реализованы. Проверка работоспособности приложения выполняется вручную с помощью командной строки.

#### 1. Проверка корректного запуска

Команда:

```
python3 src/main.py \
    --package serde \
    --repository ./repository.json \
    --test-mode true \
    --version 1.0.0 \
    --output graph.png \
    --filter test
```

Ожидаемый результат: приложение выводит все шесть параметров в формате «ключ — значение».

#### 2. Проверка допустимых значений режима тестирования

Проверка положительного значения:

```
python3 src/main.py --package serde --repository ./repository.json --test-mode true --version 1.0.0 --output graph.png --filter test
```

Проверка отрицательного значения:

```
python3 src/main.py --package serde --repository ./repository.json --test-mode false --version 1.0.0 --output graph.png --filter test
```

Ожидаемый результат: обе команды завершаются без ошибки проверки режима. В выводе `test_mode` принимает значение `True` или `False` соответственно.

#### 3. Проверка недопустимого значения режима

Команда:

```
python3 src/main.py --package serde --repository ./repository.json --test-mode maybe --version 1.0.0 --output graph.png --filter test
```

Ожидаемый результат: приложение сообщает об ошибке, поскольку допустимы только значения `true` и `false`.

#### 4. Проверка пустых значений параметров

Для каждого строкового параметра по очереди передаётся пустая строка `""`.

Пример для имени пакета:

```
python3 src/main.py --package "" --repository ./repository.json --test-mode true --version 1.0.0 --output graph.png --filter test
```

Аналогично проверить параметры `--repository`, `--version`, `--output` и `--filter`, передавая вместо их значений `""`.

Ожидаемый результат: приложение сообщает, что значение не должно быть пустым.

#### 5. Проверка отсутствующего обязательного параметра

Команда без параметра `--filter`:

```
python3 src/main.py --package serde --repository ./repository.json --test-mode true --version 1.0.0 --output graph.png
```

Ожидаемый результат: приложение сообщает об отсутствии обязательного аргумента.

## Этап 2. Получение прямых зависимостей пакета

На втором этапе реализовано получение прямых зависимостей пакетов в формате Rust (Cargo) с использованием API репозитория crates.io.

Для получения зависимостей используются имя пакета, его версия и URL репозитория.

Программа формирует HTTP-запрос к API crates.io, получает ответ в формате JSON и извлекает из него список прямых зависимостей.

Для каждой зависимости выводятся:
- имя пакета;
- требуемая версия;
- тип зависимости (`normal`, `dev` или `build`);
- признак необязательной зависимости (`True` или `False`).

### Пример запуска

```
python3 src/main.py \
    --package tauri \
    --repository https://crates.io/crates/tauri/2.12.5/dependencies \
    --test-mode false \
    --version 2.12.5 \
    --output graph.png \
    --filter ta
```

## Этап 3. Построение графа транзитивных зависимостей

На третьем этапе реализовано построение графа зависимостей пакетов с учётом транзитивных зависимостей. Для обхода графа используется алгоритм **BFS (Breadth-First Search)** — поиск в ширину (без рекурсии).

### 1. Алгоритм построения графа

Для обхода графа используются две основные структуры данных:

- `queue` — очередь, в которой хранятся пакеты, ожидающие обработки. Реализована с помощью `deque`.
- `visited` — множество уже посещённых пакетов, которое предотвращает повторную обработку одного и того же пакета.

Алгоритм работает следующим образом:

1. В очередь добавляется исходный пакет.
2. Из очереди извлекается первый пакет.
3. Проверяется, был ли он уже обработан. Если да, программа переходит к следующему элементу очереди.
4. Пакет добавляется в множество `visited`.
5. Проверяется, содержит ли название пакета заданную подстроку-фильтр. Если содержит, пакет пропускается.
6. Получаются зависимости текущего пакета.
7. Зависимости добавляются в граф и помещаются в очередь для дальнейшей обработки.
8. Алгоритм повторяется, пока очередь не станет пустой.

Таким образом, программа последовательно обходит не только прямые, но и транзитивные зависимости пакетов.

### 2. Режимы получения зависимостей

Реализовано два режима работы программы.

**Обычный режим (`--test-mode false`)**

Для получения информации используется API репозитория crates.io.

- Для исходного пакета используется версия, указанная пользователем.
- Для транзитивных пакетов запрашивается последняя стабильная версия.
- После получения версии запрашиваются зависимости соответствующего пакета.
- Из полученных данных извлекаются названия зависимых пакетов.

Для получения последней стабильной версии используется поле `max_stable_version` API crates.io. Если оно отсутствует, используется `max_version`.

**Тестовый режим (`--test-mode true`)**

Вместо обращения к внешнему API программа загружает описание графа из JSON-файла.

Файл содержит названия пакетов и списки их зависимостей. Это позволяет проверять работу алгоритма на заранее подготовленных графах, в том числе с циклами и пакетами, подходящими под фильтр.

### 3. Фильтрация пакетов

Реализована фильтрация по подстроке, передаваемой через параметр `--filter`.

Если название пакета содержит указанную подстроку, он исключается из графа.

Также не добавляются рёбра, ведущие к исключённым пакетам.

Например, при фильтре `B` исключаются пакеты `B` и `BB`, поскольку оба названия содержат указанную букву.

### 4. Обработка циклов

Для предотвращения бесконечного обхода используется множество `visited`.

Если пакет уже был обработан, повторно его зависимости не запрашиваются.

Например, для графа:

```text
A → B → C → A
```

алгоритм обработает пакеты `A`, `B` и `C`, а при повторном обнаружении `A` пропустит его.

Таким образом, наличие циклических зависимостей не приводит к бесконечному выполнению программы.

### 5. Ограничение количества пакетов

Для ограничения продолжительности обхода в программе используется параметр:

```python
max_packages = 10
```

После добавления очередного пакета в `visited` проверяется количество посещённых пакетов:

```python
if len(visited) > max_packages:
    break
```

Если количество посещённых пакетов становится больше 10, обход прекращается.

**Особенность реализации:** при текущем условии программа может добавить в `visited` 11 пакетов. При этом зависимости одиннадцатого пакета уже не запрашиваются.

Ограничение используется для сокращения времени выполнения при работе с большими реальными репозиториями. Поэтому в обычном режиме полученный граф может содержать не все транзитивные зависимости.

### 6. Тестирование

Для проверки работы третьего этапа подготовлены три тестовых файла:

- `normal.json` — обычный граф зависимостей;
- `cycle.json` — граф с циклическими зависимостями;
- `filter.json` — граф для проверки фильтрации по подстроке.

Тесты запускаются из корневой папки проекта.

#### Тест 1. Обычный граф зависимостей

Файл `tests/normal.json`:

```json
{
    "A": ["B", "C"],
    "B": ["D", "E"],
    "C": ["F"],
    "D": ["G"],
    "E": [],
    "F": [],
    "G": []
}
```

Команда запуска:

```
python src/main.py \
  --package A \
  --repository tests/normal.json \
  --test-mode true \
  --version 1.0 \
  --output graph.png \
  --filter test
```

Ожидаемый результат:

```python
{
    'A': ['B', 'C'],
    'B': ['D', 'E'],
    'C': ['F'],
    'D': ['G'],
    'E': [],
    'F': [],
    'G': []
}
```

Проверяется получение прямых и транзитивных зависимостей.

#### Тест 2. Обработка циклических зависимостей

Файл `tests/cycle.json`:

```json
{
    "A": ["B"],
    "B": ["C"],
    "C": ["A"]
}
```

Команда запуска:

```
python src/main.py \
  --package A \
  --repository tests/cycle.json \
  --test-mode true \
  --version 1.0 \
  --output graph.png \
  --filter test
```

Ожидаемый результат:

```python
{
    'A': ['B'],
    'B': ['C'],
    'C': ['A']
}
```

Проверяется корректная обработка циклов. Каждый пакет обрабатывается только один раз, поэтому программа завершается без бесконечного обхода.

#### Тест 3. Фильтрация по подстроке

Файл `tests/filter.json`:

```json
{
    "A": ["B", "C"],
    "B": ["D"],
    "C": ["BB", "E"],
    "BB": ["F"],
    "D": [],
    "E": [],
    "F": []
}
```

Команда запуска:

```
python src/main.py \
  --package A \
  --repository tests/filter.json \
  --test-mode true \
  --version 1.0 \
  --output graph.png \
  --filter B
```

Ожидаемый результат:

```python
{
    'A': ['C'],
    'C': ['E'],
    'E': []
}
```

Проверяется исключение пакетов, содержащих подстроку `B` в названии, а также удаление рёбер, ведущих к таким пакетам.

#### Тест 4. Получение зависимостей в обычном режиме

Для проверки обычного режима используется реальный пакет `tauri` из репозитория crates.io версии `2.12.5`.

Команда запуска:

```bash
python src/main.py \
  --package tauri \
  --repository https://crates.io/crates/tauri/2.12.5/dependencies \
  --test-mode false \
  --version 2.12.5 \
  --output graph.png \
  --filter test
```

В данном режиме программа обращается к API crates.io для получения информации о пакете и его зависимостях.

**Параметры тестирования:**

- Исходный пакет: `tauri`.
- Версия: `2.12.5`.
- Режим тестирования: отключён (`false`).
- Фильтр: `test`.

Проверяется получение прямых и транзитивных зависимостей реального Rust-пакета, а также построение графа с использованием алгоритма BFS.

В отличие от тестового режима, зависимости загружаются из внешнего репозитория, а не из заранее подготовленного JSON-файла.
